# Workbench 4.0.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Ship the existing Workbench as a focused, installable standard-document editor with real AI-assisted research and portable exports.

**Architecture:** Retain the Tauri shell and native secure services. Add a focused standard-document command module and replace the active legacy renderer with a smaller three-pane editor. Keep low-level regression coverage.

**Tech Stack:** Tauri 2, Rust, JavaScript ES modules, Deno tests, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-26-workbench-4-design.md`

## Global Constraints

- Only the authorized `workbench-4.0.0-Goorul` branch, new `v4.0.0-Goorul` tag and matching release are publish targets; never modify main or overwrite existing published refs/assets.
- Standard files, no proprietary project format. Preserve original binary documents.
- No fake runtime API results; no development calls to paid AI without configured authorization.
- Both sidebars collapsible and drag-resizable; preserve keyboard access.
- Delivery HTML report must not enter this repository.

## Review Focus

- Untrusted document text, filenames and URLs must not become executable HTML or escape selected filesystem scope.
- External edits, repeated clicks and interrupted saves must not silently lose content.
- Missing/rejected credentials, network errors and malformed model responses must be honest, recoverable states.
- Media references must survive save/export, with unsupported media called out rather than silently dropped.
- A release must point to the exact tested source commit and contain real validated platform installers.

## Task 1 — Standard document/native workflow

**Files:** create `src-tauri/src/standard_workbench.rs`; minimally register commands in `src-tauri/src/lib.rs`.

**Interfaces:** all commands use `{input: {...}}`: `wb_document_open`, `wb_folder_list`, `wb_document_save`, `wb_document_export`, `wb_document_analyze`, `wb_resource_search`, `wb_source_read`, and bounded media preview support. Document response includes source/save path, source hash, title, Markdown, chapter/media metadata and warnings. Markdown remains authoritative.

- [ ] Write failing Rust tests for chapter parsing, safe Markdown save/CAS, unsafe links/paths, DOCX/PPTX ZIP contents and style guide agreement.
- [ ] Implement the command module by reusing existing bounded parsers, credentials, request validation and exporters.
- [ ] Verify native tests and align exact IPC structures with the UI worker.

## Task 2 — Focused production interface

**Files:** create `app/workbench.js`, `app/workbench.css` and focused pure editor module/tests; modify `app/boot.js` and `app/index.html`.

**Interfaces:** consume Task 1 commands through the existing Tauri invoke convention; use existing safe credential configuration commands. Pure editor functions parse/edit/serialize standard Markdown.

- [ ] Write and run failing model/runtime tests for block ordering, escaping, source preservation and pane sizing/state.
- [ ] Build three-pane chapter editor, import/save/AI/discovery/export/settings flows, original logo and honest errors.
- [ ] Verify new tests, unchanged low-level suite and actual rendered UI including repeated/interrupted flows.
