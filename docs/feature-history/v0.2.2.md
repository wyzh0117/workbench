## 这个版本用户能做什么新事情？

- **在素材库里直接看到素材的内容**，而不是只看一个文件名。具体新增的可预览类型：图片和 GIF 可以放大、PDF 可以看首页、视频和音频可以播放、Markdown 可以直接读。其他文档格式（比如 DOCX）仍然以「参考文件卡片」的形式提供——你能拿到它、能打开它，但界面里不给你内嵌预览。
- **换服务商域名时，密钥不会跟着偷偷发出去。** 当某个 AI 服务商的服务域名发生变化，Workbench 会先问你是否确认，才把保存的密钥发往新域名；带鉴权的请求使用你已保存的那个连接端点。这是把一个凭据外流的口子堵上了。
- **AI 报错终于说的是人话**。服务商返回 HTTP 401（密钥不对 / 被拒）和「你根本还没配密钥」是两种完全不同的情况，现在会区分开，并且提示你去检查连接 URL 与鉴权设置。
- **把文件加进素材库，但不自动挂到当前课。** 加进来的素材可以先待在库里，由你单独决定它用在哪一课。
- **把课程地图整理得更顺手**：阶段可以重命名、调序、**折叠**，课次标题可以直接在原地改（inline）。

## 哪些操作方式发生了变化？

- **「添加素材」不再等于「插入到当前课」。** 这是最明显的一个习惯改变：以前导入的素材会被自动附加到当前选中的课程上下文，现在只进素材库，挂载这一步是你自己单独做的。实测证据：只执行「添加素材」导入一个 957B 的 DOCX 之后，界面显示「还没有被任何内容引用」，磁盘上素材数 11→12、引用数保持 1→1、区块数 0→0。
- **素材预览改成懒加载**：卡片滚动进入视口才加载。屏幕外的卡片会明确显示「等待加载」的状态，而不是空白一片；预览失败时显示可用的错误说明，并提供一个**重试**动作。实测例子：一张离屏的第 10 张卡先显示「等待加载 smoke-text.txt」，向下滚两页进入视口后约 1.36 秒显示出内容。
- **课程地图新增折叠操作**，阶段菜单的键盘焦点与改名行为收口。
- **不支持内嵌预览的文档格式走「参考文件卡片」这一条明确路径**（实测：导入一个有效的最小 DOCX 后，界面显示「参考文件 · 当前环境没有内嵌缩略图」，没有读取或解码错误）。

## 哪些旧问题被修复？

- **离屏素材卡的状态含糊**：滚动进入视口前只显示空白，现在改成明确的「等待加载」；失败的预览以前不给反馈，现在给错误说明 + 重试。
- **AI 401 被误报成「缺少密钥」**：现在能区分鉴权失败和未配置密钥，并给出对应的排查方向。
- **「添加素材」的副作用**：导入动作会自动把素材附加到当前课程上下文（commit `202e6e4` 修复）。
- **跨阶段拖放丢身份**：真实跨阶段拖放 S01-02 → S02-01 之后，课时 ID、文档 ID 与标题保持稳定，目标阶段与 order 正确写入磁盘，Undo / Redo 之后界面与磁盘状态都对。
- **导入资产时被自动建立引用**：修复后新导入的素材不产生 usage（`956be88` / `202e6e4`）。

原生 0.2.2 WKWebView 实测通过的项：PDF blob iframe 预览、PNG / GIF 放大、MP4 / WAV / Markdown 预览、损坏 / 空白 / 缺失图片三种情况的错误区分与重试、地图阶段折叠与展开、阶段菜单焦点与改名、阶段 / 课次标题编辑及 Undo / Redo、发布预检显示 0 个必须修复项与 0 个提示（**未点击开始导出**）。预检前后隔离 fixture 的 `project.json` SHA-256 完全一致（`e94063dc…e43cde`），资产、备份与 index 文件名和 hash 都相同，只有运行时 `project.lock` 变化——即这一版对导出预检是真正只读的。

## 兼容性或迁移变化

Release 正文与总控 §39 **没有记录任何版本间的兼容性或数据迁移变更**：没有要求转换旧项目，`project.json` 格式没有记录破坏性改动。

只有一条与上一节相关的既有数据行为需要知道（来自 §39.4）：改成「添加素材不再自动挂载」之后，**旧项目里已经存在的素材引用会被保留，不会被自动清理**。也就是说这个行为变化只影响新导入的素材，不会回头改你过去建立的引用关系。

`v0.2.2` 的 tag 与 DMG 资产保持冻结，后续修复走新版本（这一条在 §39.1 与 §39.4 都写明）。
