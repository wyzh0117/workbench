## 这个版本用户能做什么新事情？

- **在 Grid 布局里真正使用「页」。** 页有稳定的编号，可以编辑顺序和尺寸，已经放好的内容可以在页之间移动。也就是说，一门课现在可以是「一组页」，而不只是一张连续的长网格。
- **按页导出成三种成品**：分页 HTML、分页 PDF、以及 PowerPoint（PPTX）。**PPTX 的页与幻灯片一一对应**，而且**文字和图片是分开的、可分别编辑的对象**——导出到 PowerPoint 之后不是一整张贴图，你可以在 PowerPoint 里直接改文字、单独挪图片。Release 记录里 PowerPoint 打开三页 PPTX 样例时没有触发 Repair，文字与图片对象分别可编辑并能保存。
- **混尺寸页面也能得到一个统一的成品尺寸。** 当课程里各页尺寸不一致时，可以预览一个公共输出尺寸。
- **把旧的连续网格段落改造成分页，而且改造成之前先看清会发生什么**：确认之前，原有布局数据保持完整不动。
- **导出前的提示绑在你正在导出的那一份内容上。** 预检（preflight）的 WARNING 是和确切的项目快照 revision 绑定的：你必须处理的分块布局 / 素材问题，**不能靠「我已确认这些提示」绕过去**。

## 哪些操作方式发生了变化？

- **PDF 与 PPTX 在源页尺寸不一致时，必须显式指定目标尺寸**才会导出。没有指定时会被阻断（记录里的错误码是 `explicit_target_page_size_required`），而不是被静默地猜一个尺寸。
- **导出确认动作变严了**：确认 WARNING 只表示你看到了那些提示，不再等于放行了 BLOCKING 问题。
- **进入分页编辑后有一个明确的「完成分页编辑」退出动作**，页面与栅格位置按分页方式管理（这一项在 v0.2.3 的反馈收口里还在继续打磨）。
- **跨页移动内容成为常规操作**：已放置的内容可以从一页挪到另一页。

## 哪些旧问题被修复？

- **macOS 发布流程在没有 Apple 签名证书时会失败**：现在没有证书就不再尝试导入空的证书值，而是直接走 ad-hoc 签名回退。这正是 `v0.2.0` 当时发布失败的原因（workflow run `36323485548` 因空 `APPLE_CERTIFICATE` 导入而 `failure`），修好之后 `v0.2.1` 发布成功。
- 独立复核发现并修复的几项（`PROJECT_MASTER_CONTROL.md` §38.2）：旧 schema 的迁移处理、复杂 clone 的 identities / anchors、分页 HTML 的 selected scope、legacy Grid 预览、以及多段落（multi-section）时的歧义。
- 桌面端启动时首次 `load_session` 只返回 locator、导致关闭重开后回不到已保存页的根因被修复；修复后同一个隔离项目连续两次 close/restart 都能恢复到第 3 页，最终 Universal 构建同样恢复第 3 页，`layout_page_id`、缩放和 canonical 项目路径保持正确（§38.3）。

## 兼容性或迁移变化

这一版有明确的迁移设计，而且刻意做得保守：

- **旧项目继续可用**：`layout_pages` 与稳定 page ID 接入现有 Domain / Store / UI 和分页预览，**旧项目保留迁移路径与连续布局兼容**（§38.2）——不会因为升级就打不开老课程。
- **legacy 连续 Grid 段落 → 分页的转换需要你确认**；在确认之前，现有布局数据保持原样完整。也就是说，不确认就不会改你的东西。
- **已发布的 tag 全部保持冻结**：`v0.2.0` 的 tag 未移动、未删除，只是没有 Release；`v0.1.x` 的 tags 与资产也没有被改写。公开发布的唯一路径仍然是**推送新的 `v*` tag**（`workflow_dispatch` 即使选中 tag 也只构建、不发布）。

## 已知限制

- **未签名、未公证**：公开 DMG 为 ad-hoc 签名，无 Apple Developer ID 签名、无公证。Release 正文「Distribution status」原话：`NOT signed with an Apple Developer ID and NOT notarized`。首次打开仍需手动过一次 Gatekeeper（macOS 15+ 走「系统设置 → 隐私与安全性 → 仍要打开」，Control-click 已无法绕过；macOS 11–14 走右键 → 打开），并且不建议关闭 Gatekeeper 或用 `xattr` 移除隔离属性。
- **放行之后的首次启动未实测**：实测到的只有放行**之前**的拦截状态（匿名下载公开文件、公开 `.sha256` sidecar 与 GitHub asset digest 一致、`hdiutil verify` 为 VALID、bundle version 0.2.1、架构 x86_64 + arm64）。
- **尚未完成真实在线 AI Provider 调用验收**：本版 Release 正文未涉及在线 AI 能力，AI 走通闭环使用的仍是离线连接器；真实 Provider 没有一次在线 smoke。
- **原生 PDF 与 PPTX 的导出实测来自隔离项目**（三页样例），不是在最终公开发布的包上重跑整套 GUI 验收。
- **PNG / JPG 位图输出与复杂长图海报系统为明确的非目标。**
- **Windows / Linux 不支持。**
