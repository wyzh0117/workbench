## 这个版本用户能做什么新事情？

- **用行卡片管理 AI 服务商。** 打开 AI 设置→模型，每个服务商是一张行卡：显示名、「凭据已配置 / 未配置凭据」状态点、「当前使用」标记一眼可见；点「编辑」在行内展开编辑卡，点「使用」切换当前连接，点「删除」连同本机密钥一起删除（会先确认）。
- **在行内编辑卡里配好一个连接。** 卡片第一屏就是 API 密钥输入（有已保存密钥时提示「留空使用已保存凭据」，可「显示密钥 / 隐藏密钥」切换）；显示名称、API 地址、API 协议、模型目录收进「自定义设置」折叠区，不干扰最常用的一步。保存、取消、测试连接都在卡内，保存成功会显示「已保存 {显示名}。」。
- **按类型分段添加提供商。** 底部虚线通栏「＋ 添加模型提供商」展开新增卡，三段分段控件「第三方模型提供商 / 自定义模型 API / 订阅登录」各带一句用途说明；切换分段不会丢掉已经填过的内容。订阅登录仍是既有的 ChatGPT 订阅流程。
- **把模型目录当成可编辑的清单。** 每个模型一行：Model ID、显示名称、上下文窗口、最大输出 token（支持 K / M 后缀，K=1000、M=1000000）、输入类型（文本 / 图片）勾选；行可上移 / 下移排序、可移除、可「手动添加 Model ID」，也可「恢复默认模型」（会先确认丢弃当前编辑）。
- **从服务商获取真实模型列表并勾选。** 「获取可用模型」向连接的服务商探测，打开「选择模型」弹窗：可搜索、全选 / 清空，**勾选的模型就是模型列表**，点「更新列表」按勾选结果落定（含移除未勾选项）。
- **给单个模型配推理等级。** 模型行打开「推理等级」开关后，可添加档位（off / minimal / low / medium / high / xhigh / max）并为每个思考档位填写「API 参数值」；发请求时按协议注入：OpenAI 系协议写 `reasoning_effort`，Anthropic Messages 在参数值为纯数字时写 `thinking.budget_tokens`。

## 哪些操作方式发生了变化？

改造前后对照（截图均为浏览器壳真实渲染，见[对照证据](../reports/evidence/ai-model-config-2026-10-24/README.md)）：

- **旧**（[`01-before-modal.png`](../reports/evidence/ai-model-config-2026-10-24/01-before-modal.png)）：AI 设置弹窗是「AI 模型」标题下的**单个表单**，配上「已有模型服务商」列表、绿色的「+ 添加模型服务商」按钮和底部**固定订阅区**；新增服务商就是把所有字段摊在一个表单里填。
  **新**（[`02-after-modal.png`](../reports/evidence/ai-model-config-2026-10-24/02-after-modal.png)）：标题「模型」、引言「填入各提供商的 API 密钥即可使用其模型。」，主体是**提供商行卡列表**，点「编辑」在**所属行内**展开编辑卡（一次只展开一张，草稿互不丢弃）。
- **添加提供商从「单按钮 + 单表单」改为「虚线通栏入口 + 分段添加卡」**（[`03-after-add-card.png`](../reports/evidence/ai-model-config-2026-10-24/03-after-add-card.png)）：新增卡顶部是分段控件「第三方模型提供商 / 自定义模型 API / 订阅登录」，各有一句逐字用途说明；创建表单字段顺序固定为 Provider ID → 显示名称 → API 地址 → API 协议 → API 密钥。**固定订阅区不再常驻弹窗底部**，订阅登录成为「订阅登录」分段。
- **模型清单从「ID 列表」改为「模型行编辑」**（[`04-after-model-row.png`](../reports/evidence/ai-model-config-2026-10-24/04-after-model-row.png)）：逐模型编辑显示名、上下文窗口 / 最大输出 token（两列）、输入类型，并用 ↑ / ↓ 调整顺序。
- **「读取模型」改为「获取可用模型 → 选择模型弹窗 → 更新列表」**：勾选即目录；探测失败仍是「读取模型失败：{原因}」提示，可以直接手动填 Model ID，不影响保存。
- **新增「推理等级」**（[`05-reasoning-tiers.png`](../reports/evidence/ai-model-config-2026-10-24/05-reasoning-tiers.png)）：档位 / API 参数值成对编辑，off 行表示关闭思考且不下发参数。**未点名档位的请求默认取该模型已配置的最强思考档**（off › minimal › low › medium › high › xhigh › max），执行记录会显示实际使用的档位并在使用默认档时说明「未选择档位，使用最强档 {档位}」。
- 弹窗底部保留一句安全说明：AI 配置仅保存连接元数据，密钥和订阅令牌写入本机系统钥匙串，课程文件不含凭据。

## 哪些旧问题被修复？

本轮以界面与逻辑重做为目标，**没有单独的缺陷修复条目（无记录）**。随重做一并解决的旧界面表达问题：

- **模型目录不再只是一串 Model ID。** 旧界面无法逐模型声明显示名、容量、输入类型和推理能力；现在这些都能在模型行里编辑，并随连接配置持久化（`model_meta`，设计 §4.3）。
- **三种接入方式不再挤在一个表单里。** 旧的单表单 + 固定订阅区把第三方兼容 API、自定义模型 API、订阅登录混在一起；现在新增卡按类型分段，逐段说明用途。
- **推理参数此前完全不随请求下发。** 现在按协议注入（OpenAI 系写 `reasoning_effort`，Anthropic Messages 写 `thinking.budget_tokens`），且只对显式打开推理等级的模型注入，off 档位不写任何推理参数（设计 §4.4）。
- **配置校验两端一致。** `model_meta` 在 Deno / TS 与 Rust 两侧按同一套规则校验（字段白名单、正整数容量、档位枚举、输入类型至少一种），并保持 8KB / 深度 4 的既有限额与凭据形状字段拒绝规则；桌面壳读写 `providers.json` 往返等值。

## 兼容性或迁移变化

- **旧配置继续可用，不需要迁移。** 没有 `model_meta` 的旧连接按「未声明」处理：容量留空 = 使用提供商默认值，输入类型默认「文本」；保存按字段合并，缺省 `model_meta` 保留旧值，要清空必须显式提交空的 `model_meta`。未知模型 id 的元数据条目保留（不猜、不删）。
- **已保存的 API 密钥与订阅令牌不需要重新输入**：密钥仍只写、只进本机系统钥匙串，不进界面状态、会话或课程文件；临时密钥输入在关闭、取消、保存后都会清空。
- **桌面壳落盘 `providers.json` 的键序为字典序**（Rust `serde_json` 对象按 BTreeMap 排序）；与浏览器壳写出的 JSON 文本不保证逐字一致，跨壳比较请按值等值，不按文本比对。
- **版本号 3.0.1 已同步写入** `src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock`。
- **仓库状态（非用户可见功能）**：main 分支此前停在 v0.2.7，v3.0.0 发布自 workbench-3.0.0 分支；合并提交 `1845af0` 把 v3.0.0 发布线收进 main，本次改造叠在其上。v3.0.0 的用户可见能力仍归属 v3.0.0，不计入本版。

## 已知限制

- **没有内置厂商预置目录 / 模板（产品红线，设计 §1 与 §9.2）。** 添加提供商时不提供任何厂商预设：端点、API 协议、模型全由自己填写，或用「获取可用模型」探测；不会替你预填任何服务商默认值。
- **推理档位默认取最强档，且暂无请求级档位选择器。** 未点名档位时使用该模型已配置的最强思考档（设计 §4.4.1 裁决）；DSH 由会话 composer 提供请求级档位选择，本项目没有该组件。开关打开即视为同意注入；执行记录会显示实际使用的档位并在使用默认档时注明。
- **`max_tokens` 仅在 `model_meta.<id>.max_tokens` 这一固定槽位豁免凭据字段名规则**（设计 §4.3.1 裁决）：该槽位取值被类型锁死为正整数，字符串密钥藏不进去；其它任何层级的 `max_tokens` 仍照常拒绝。连带限制：模型 id 若含 key / token / secret / credential / password / authorization 子串，则该 id 不能带 `model_meta` 条目（`models` 数组本身不受影响）。
- **桌面壳落盘键序为字典序。** `providers.json` 的 JSON 文本顺序在两个壳之间不逐字一致，比对请按值等值（见上文兼容性）。
- **Anthropic Messages 的非数字参数值不下发思考参数**：档位 API 参数值不是纯数字时，不写 `thinking`、不抛错、不打断请求，以 warning 透传并给出下一步提示。
- **真实在线服务商请求「无记录」。** 本次证据目录是浏览器壳 `deno task ui` 的真实渲染截图；带真实密钥、真实计费的端到端请求在本次证据中无记录，不作声称。
- **发布产物校验为「发布后补记」。** 本文件写就时 tag、Release、安装包大小 / SHA-256 / 验签结果均无记录，打 tag 公开发布后按 workflow 实际判定回填（签名与公证状态以 workflow 判定为准，本文不预先声称）。
