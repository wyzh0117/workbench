# v3.0.0 — Public release 2026-10-21

The user accepted the documented PARTIAL and UNVERIFIED limits and authorized the v3.0.0 release on 2026-10-21. This release record describes tag `v3.0.0`; the authorization does not change any individual acceptance status.

## What's new

- A unified course workspace keeps course structure, lesson work, resources, and settings together. Lesson completion is separate from layout status.
- Users can build a bounded case/video search plan from selected course materials, review source and collection details, and explicitly save or cite a candidate. Brave Search and YouTube credentials are configured separately from AI credentials. Reusing an existing resource for another lesson creates a separate usage; merging a different candidate's source requires selecting the resource and confirming the same-event match.
- Users can record manually checked video clip times with an explicit confirmation. This records timing evidence only; it does not claim transcript or caption verification.
- Users can extract an editable style profile from a PowerPoint, review structural SVG previews and visual inferences, and propose a supplemental slide through the existing AI connection with explicit context consent. A manual editable draft remains available. After preview, a slide can be exported as a single-slide file or an appended copy; the original is preserved.

## Acceptance and known limits

See the [32-item acceptance record](../v3.0.0-acceptance.md) and [UI/performance evidence](../acceptance/v3.0.0/README.md). The matrix remains mixed PASS, PARTIAL, and UNVERIFIED; the user explicitly accepted those limits for this release.

- Live Brave Search, YouTube, and AI inference were not tested with real credentials.
- The production codec was exercised on two public MIT OCW PPTX samples (23 slides and 8 slides); source pages, hashes, the receipt, and ten output package hashes are in [PPTX sample evidence](../acceptance/v3.0.0/pptx-real-samples.md). This is package-level evidence only; each sample has one master and they do not establish two distinct courseware classes. Real multi-master courseware, legacy `.ppt`, broader damaged-package cases, and PowerPoint open, no-Repair status, editability, save, and reopen remain unverified; a truncated package was rejected in a separate probe.
- Structural SVG previews are not Office renders. True 150%/200% text scaling and real IME input remain unverified, and PERF-01 is partial because a fresh task return at representative media-library scale was unavailable.
- The first local `.app` build without an explicit signing identity failed `codesign --verify --deep --strict` with a resource-sealing error. Rebuilding with the release workflow's `APPLE_SIGNING_IDENTITY='-'` passed strict verification; this is ad-hoc signing with no Team ID, not Developer ID signing or notarization. The corresponding ARM64 DMG passed `hdiutil verify`; an earlier sandboxed DMG attempt failed with `hdiutil: Device not configured`, then the controlled rerun passed without packaging changes. The release workflow now gates asset staging on strict app verification.

The implementation candidate is commit `f1de6643c0d2cb9023bfbf42a87d85a870adb2fa`. Workflow/version-check commit `2775c9d2aecff38caa95622859206233a0770c6a` was verified by the corrected [build-only run](https://github.com/wyzh0117/workbench/actions/runs/39482060115) (`workflow_dispatch`); macOS and Windows jobs passed, and the GitHub Release job was skipped. The macOS app passed `codesign --verify --deep --strict`; `lipo` reported `x86_64 arm64`. It is ad-hoc signed with no Team ID and is not notarized. The Windows installer version resource reported ProductVersion/FileVersion `3.0.0` and ProductName `AI Course Workbench`.
