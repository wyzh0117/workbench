## 这个版本用户能做什么新事情？

这一版主要是「把 v0.1.0 里用起来会卡住的地方修好」，但确实新增了几件用户以前做不到的事：

- **能看到并选择服务商真实存在的模型。** 新增了真实的模型枚举：填好 Base URL 后点「读取模型」，Workbench 会去问服务商本身（`GET {base_url}/models`）有哪些模型可用，读到的结果直接点选就行。不再依赖任何硬编码的模型清单——也就是说，服务商上新模型不需要等 Workbench 更新。
- **读取失败时仍然能用。** 模型读取失败不会把你堵死：手动输入 Model ID 是一个明确写在界面上的出口，照样能保存、照样能用。
- **区块高度会自己适应内容。** 短内容（标题 / 引用 / 提示 / 分隔线 / 占位符）从小档升到中档就封顶；长内容（正文 / 代码 / 列表 / 练习）在中档和大档之间调整。打字时高度即时跟随，内容变少会自动收缩；到顶之后由区块外框自己滚动，不用再手动拖拽文本框。
- **在 Grid 里真正把东西放到想要的位置。** 左键点击落位 / 进入移动状态，点击目标格直接移动，右键把内容移出网格，尺寸调整稳定可用；放不下时会明确拒绝并告诉你原因，而不是放上去再出错。网格只保存位置，不改动内容本身。
- **排序只有一个地方可改了。** Flow 每一行的 ↑↓ 直接写回真实顺序，结构视图不再提供第二个排序入口——不存在「两处顺序不一致」这种情况。
- **每个区块都有自己的拖拽把手**，新建的区块会立刻被选中并打开属性面板，不用再做一次多余操作。
- **课程地图会逐课告诉你缺什么**；seed（种子/示例生成）只产生草稿，你确认之后才会建立正式结构。状态栏永远说明「现在改的是谁」。
- **Flow / Grid 预览和真实网格一致**，并且会列出还没有上画布的正文，让你知道漏了什么。

## 哪些操作方式发生了变化？

这些是相对 v0.1.0 的**操作习惯变化**，v0.1.0 的用户需要重新适应：

- **Provider / Model 配置整个重做**：新的顺序是 Base URL → 读取模型 → 选择或手动输入 Model ID → 保存。密钥仍然由单独的「保存密钥」动作写入系统钥匙串，配置表单里只放地址与模型名。
- **排序入口收敛到 Flow**：结构视图里的排序操作**取消了**。想改顺序只能去 Flow 的每行 ↑↓。
- **Grid 交互重设计**：左键 = 落位 / 进入移动状态、点目标格 = 直接移动、右键 = 移出网格。
- **API Key 的「已配置密钥」不再提前显示**：只有真正写入并且能读回时才显示已配置；失败会说明是权限问题还是写入问题。
- **弹窗行为变了**：弹窗内的点击 / 展开不再误关弹窗，而且弹窗一打开光标就落在该填的输入框里。
- **中文输入法期间不再重渲染**，输入、保存、状态栏更新和 toast 不再互相打断。

## 哪些旧问题被修复？

**真实使用阻断（P0）**

- 项目选择：同一个项目可以反复打开了；换项目走真实的文件夹选择；失败会给出具体原因，不再静默无反应。
- 输入：输入、保存、状态栏更新与 toast 不再互相打断；中文输入法组字期间不重渲染。
- 弹窗：弹窗内点击 / 展开不再误关；打开即把光标放进该填的输入框。
- API Key：只有真正写入并能读回才显示「已配置密钥」；失败会说明是权限还是写入问题。
- Block：每个区块有拖拽把手；新建区块立刻选中并打开属性面板。
- Flow / Grid：放置、移出、缩放稳定；预览与真实网格一致；列出还没上画布的正文。
- 课程地图：逐课说明缺什么；seed 只生成草稿、确认后才建正式结构；状态栏永远说明「现在改的是谁」。

**Authoring 直觉问题（P1）**：课程地图 / 单课编辑器 / 待补 / 素材相关的十项直觉性问题全部落地，每一项都有回归测试保护。

**本轮额外发现并修复的**（这些不在原计划里，是做的过程中挖出来的真实故障）

- 桌面壳缺少 `course.seed.create` / `blueprint.build` 命令映射——点「把材料变成课程地图」会**直接失败**。
- 沙箱内写入被拒时，提示显示成「项目被占用」这种**误导性文案**；改成如实说明是写入权限问题。
- 新建 Block 后，属性面板要等到下一次无关渲染才切换过去。
- **所有**弹窗打开时都不接管输入焦点，第一次输入的内容直接丢失。

自动化侧从 v0.1.0 的 236 增至 266 passed / 0 failed（`cargo test` 55 passed / 0 failed），这是上面那些回归保护的规模。

## 兼容性或迁移变化

- **必须重新下载安装包。** Release 正文原话：`v0.1.0` 的安装包构建自较早的提交，**不包含**上面这些修复；`v0.1.1` 是按当前 `main` 重新构建的最新安装包。所以只装了 v0.1.0 的用户，那些 P0/P1/P2 的改善一个都拿不到。
- **不再依赖硬编码模型清单。** `providers.json` 只保留元数据（`base_url` / `default_model` / `models` / 标签），密钥永远只在系统钥匙串。模型 ID 现在来自「读取」或「手动输入」两条路。
- **结构视图不再提供排序**（见上一节），旧的排序操作位置消失了。
- 系统要求、Universal 架构、固定文件名与 `latest` 直链、`.sha256` sidecar 等约定延续 v0.1.0，未变。

## 已知限制

- **尚未完成真实在线 AI Provider 调用验收**：本版走通完整闭环使用的仍是离线「本地确定性连接器」。真实 Provider 的请求组装、鉴权注入与错误码映射有自动化测试覆盖，但**没有一次真实在线 smoke**。（新增的「读取模型」是向服务商真实请求，但 Release 正文没有把在线 Provider 整体验收列为已完成。）
- **未签名、未公证**：ad-hoc 签名（走 Tauri 官方签名路径 `APPLE_SIGNING_IDENTITY="-"`）。`codesign --verify --deep --strict` 通过；`codesign -dv` 显示 `Signature=adhoc, TeamIdentifier=not set`；`spctl --assess --type execute` 判定 **rejected**。分发状态 `PARTIAL / BLOCKER = 缺正式 macOS signing / notarization credentials`。**不宣称** `PUBLIC RELEASE READY`，也**不宣称**「普通用户无安全阻碍安装」。拿到 Apple Developer 分发资格后只需补做签名、公证、重新上传 Release 与一次安装 smoke，不需要重新开发 Workbench 本体。
- **放行之后的首次启动未实测**：只实测了放行**之前**的拦截状态（本版实测的是 DMG `hdiutil verify` 判定 `VALID`，从 DMG 取出的 App `spctl --assess --type execute` 判定 `rejected`）。
- **本版未重做 v0.1.0 那次完整交互安装走查**（拖入 Applications → 三栏工作台 → AI 助手 → 关闭 → 重启）。Release 正文原话：「上面记录的是本次实际执行的验证项，没有执行的不写成已通过。」本版实际执行的是：`deno task check` 通过、`deno task test` 266 passed / 0 failed、`cargo test` 55 passed / 0 failed、`lipo -archs` = `x86_64 arm64`、`codesign` / `spctl` / `hdiutil` 如上，以及一次启动 smoke（从 DMG 取出 App → 指定项目目录启动 → 存活 10s 无崩溃 → SIGTERM graceful 退出；`--project-dir` 指向不存在的目录时按文档在开窗前退出并打印原因）。
- **PNG / JPG 位图输出与复杂长图海报系统为明确的非目标。**
- **Windows / Linux 不在本版支持范围内。**
