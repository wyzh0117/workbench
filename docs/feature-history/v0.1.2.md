## 这个版本用户能做什么新事情？

- **把一个已经存在的文件夹直接变成 Workbench 项目。** 这是这一版最重要的新能力。启动页现在是三条独立路径：**新建课程 / 打开 Workbench 项目 / 导入已有文件夹**。选「导入已有文件夹」后，Workbench 先做一次**只读扫描**并给你一个文件浏览器（Markdown、图片、视频、PDF / DOCX 的参考预览），映射关系以「建议」的形式呈现——你可以取消、可以改映射，**确认之后才写入 `project.json`**。接管是**原地**的：不移动、不改名、不删除你的原文件。
- **自己搭课程结构，不再被初始结构锁死。** 课程地图里可以直接新增、重命名、调整顺序、删除阶段。删除空阶段要两次确认；删除非空阶段会提示你先把课移走，**不会级联删除课程**。阶段的 `code` 和显示标题是分开的。
- **用指针把手拖动区块重排**（Block 排序不再只有 ↑↓）。
- **改素材的显示名称**（磁盘上的文件名不动）。
- **在一个地方浏览你选中的文件夹里的文件**，而不必先把它变成一个课程。

## 哪些操作方式发生了变化？

- **打开一个不是项目的文件夹时，不再只甩给你一句「不是可用课程项目」**：现在会说明原因、缺什么、以及下一步该做什么。
- **选中区块的方式变了**：点击文字或者点击外框都会选中 Block，左侧同步高亮，而且输入法与光标位置不会被打断。
- **`+ 媒体` 现在把媒体插到当前 Block 之后**；从媒体库点「插入到当前位置」走的是同一条路径——两个入口不再给出两种结果。
- **点击占位符现在会打开右侧的「状态」面板**；左栏多了一个可点击的「工作台」。
- **待补（TODO）的位置是真实锚点**，不再显示没用的「位置：待补」，点过去就能到那一处。
- **Small 档区块的完整外框固定为 100px**，顶栏工具不再被裁切。
- **接管已有文件夹有了一道明确的确认闸**：映射只是「建议」，确认前不写盘；相同 checksum 的素材会复用，**同名但内容不同的文件不会被静默覆盖**。

## 哪些旧问题被修复？

- 顶栏工具在窄窗口被裁切的问题。
- Small 档区块尺寸不确定、外框表现不一致的问题。
- 点击文字会打断输入法 / 丢光标的问题。
- 「位置：待补」这种无法定位的占位文案。
- 素材显示名与磁盘文件名绑死、无法单独改显示名的问题。
- 打开错误目录时提示不含任何可执行信息的问题。

## 兼容性或迁移变化

- **`v0.1.1` 已发布并冻结，本版是新 tag，没有改写 `v0.1.1` 的字节。** Release 正文原话：`v0.1.1` 仍可从历史 Release 下载。这条确立了此后所有版本的做法：已发布的 tag 与资产不可变。
- **接管已有文件夹采用「Strategy A：原地接管」**（`PROJECT_MASTER_CONTROL.md` §37.2）：在用户所选的文件夹里写入 `project.json` + `.workspace`，确认后的媒体复制到该项目下的 `assets/{id}-{filename}`；**不**移动 / 重命名 / 删除原文件。在**已经有 `project.json` 的目录上会拒绝重复接管**。当时明确没有选择「旁路 managed project / Source Root」方案，目的是避免产生第二份真相。
- 如果你的课程项目是在 v0.1.1 之前建立的，本版的结构操作（阶段增删改）与区块拖排是**在同一份 `project.json` 上工作**，不需要迁移步骤；记录里没有要求任何数据转换。

## 已知限制

以下来自本版 Release 正文自己记录的部分：

- **未签名、未公证**：本版 DMG 为 **ad-hoc 签名**，`codesign --verify --deep --strict` 通过，`spctl --assess --type execute` 判定 **rejected**。分发状态 `PARTIAL / BLOCKER = 缺正式 macOS signing / notarization credentials`。**不宣称** `PUBLIC RELEASE READY`，也不宣称「普通用户无安全阻碍安装」。首次打开仍需手动过一次 Gatekeeper（macOS 15+ 走「系统设置 → 隐私与安全性 → 仍要打开」；macOS 11–14 走右键 → 打开）。
- **原生 folder picker 在浏览器验收环境里是 N-A（无法执行）**，被记为 BACKLOG 而非 BLOCKER（`PROJECT_MASTER_CONTROL.md` §37.5）；toast 提示已验证。
- 本版 §37.5 的自动化 gate 全绿、ego-browser 走查通过，但**本轮 UI 只复走了 T04 导入链路与 session restore**，其余界面没有再人工走查一遍。

以下限制在 v0.1.0 / v0.1.1 的 Release 正文里逐条写明，**v0.1.2 的 Release 正文没有重复列出**，而没有任何记录表明它们在这一版被解决，因此继续成立：

- **尚未完成真实在线 AI Provider 调用验收**：走通闭环使用的是离线「本地确定性连接器」；真实 Provider 的请求组装、鉴权注入与错误码映射只有自动化覆盖，**没有一次真实在线 smoke**。
- **放行之后的首次启动未实测**：自动化环境无法投递右键菜单与「系统设置」交互，只实测了放行**之前**的拦截状态（本版实测到的是 `hdiutil verify` VALID、`spctl` rejected、指定项目目录存活 10s 后 SIGTERM 的启动 smoke，以及不存在的 `--project-dir` 会在开窗前退出并打印原因）。
- **PNG / JPG 位图输出与复杂长图海报系统为明确的非目标**（`PROJECT_MASTER_CONTROL.md` §34.10 / V0-T04 审计结论：导出中心不提供 png / jpg 格式卡片，`preflightExport` 对 png / jpg 报 `unsupported_format`）。
- **Windows / Linux 不支持**，也不构建它们的分发包。
