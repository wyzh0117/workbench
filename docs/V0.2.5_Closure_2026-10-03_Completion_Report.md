## Media Flicker Root Cause — 大白话说明

完整技术版（含每处修改的 file:line 与对号结果）见
[`docs/v0.2.5_media_flicker_root_cause.md`](./v0.2.5_media_flicker_root_cause.md)；
这里按 §7 的要求，用非前端开发者能听懂的话回答六个问题。

### 1. 为什么会开始反复加载？

缓存像一个只有 32 格的相册架，满了就扔最前面那张。旧版有个坏习惯：**每“看一眼”都会把照片
塞回架子末尾**——而“看一眼”只是重画屏幕时程序自己调的一次读取，不代表用户真的在看。旧版
读完一张图还会**把整页推倒重盖**（用新 DOM 替换全部卡片）。于是：新图进架 → 挤掉最前面的 →
被挤掉的那张可能正显示在屏幕上，它的图片地址同时被作废 → 卡片退回“等待加载” → 再去读一遍。

### 2. 为什么往回滚更容易触发？

扔哪一张跟着重画后的列表顺序走，架子最前面永远是最靠上的卡片。往下滚时，被扔的都是快要
滚出视野的，看不出来；往回滚时，最靠上的卡片正是马上要进视野的那批——刚加载完就被扔、
扔掉立刻重来，抽搐正好发生在眼睛盯着的方向。

### 3. 为什么最后连其他地方也无法点击？

每次预览完成都把整页推倒重盖，而重盖会主动打断正在进行的指针动作（按下与抬起之间，按的
那个元素已经被换掉了）。循环不停，重盖不停，输入永远排在后面。注：「点击落在共同祖先上」
这一环只有注释、没有断言，记为未证明；有代码依据的是「完成即整页重建」和「重盖会取消
进行中的指针动作」。

### 4. 真正是哪一个状态 / observer / async request 在循环？

一句话：**`load 完成 → notify → render（整页重建）→ observe（重新登记观察器）→ load`**。
- 状态：`ready → loading`（淘汰作废地址后，缓存里查不到就退回 loading）。
- 观察者：不是 enter/leave 抖动——旧回调对“离开视野”直接忽略；是**整页重建后所有卡片被
  重新登记**，浏览器对新登记元素必补一条“进入视野”记录。
- 异步请求：`load()` 的 `finally` 里那句 `scheduleNotify()` 是再触发点；淘汰器按插入顺序
  扔最前面并作废其图片地址。

### 5. 最终怎样修的？

把“收到一张照片就重盖整栋楼”改成“只换那一格”：预览完成只就地改写那一张卡片；整页重建
退化为最后兜底（本轮用例里 120 张卡全程 `rebuilds === 0`）。正在显示的卡片把自己的缓存
钉住（容量 = 在页卡片数 + 32 历史，硬上限 240）；真要腾内存时先重画、再作废地址，并把
卡片标成「已释放」+ 重试按钮；读取改成只读（不再重排淘汰顺序）；已落定 / 在途的卡片不再
重新登记；等待队列有界，“卡片已经没了”的排队读取就地作废。

### 6. 为什么这次修法不会继续留下同类型隐患？

循环要成立必须同时满足四件事：完成重建、显示中被淘汰、重复登记、状态机回退。现在每件事
各有一道闸门和一条测试，抽掉任意一条循环就断，且四条同时被
`media_preview_stability_test.ts` 的第一个用例钉住。几何与身份是**结构性**保证：全文件只有
一处写卡片身份字段、所有状态画在同一个盒子里——新加一个状态想绕过这个盒子，测试直接红，
不是四处分歧式打补丁。

## 3. Project Identity（§2）

- `project.id` 就是正式项目身份，是唯一身份字段；本轮**没有**引入第二个 UUID / 别名。
- 迁移（`migrateProject`，`src/domain/store.ts:2205`）对旧 schema 只做加法：补齐缺失集合、
  两处 schema 版本戳升到当前值；`project.id ??= id()` 只在**缺失**时才生成，已有 id
  逐字节保留。§32.1 断言：旧文件 → 迁移 → `project.id` 不变、迁移后零校验问题、
  serialize→parse 往返后身份不变、且不存在 `uuid` / `project_id` 等第二身份字段
  （`tests/smart_project_inspect_test.ts`）。
- 打开分类器（`inspectProjectData` / `inspectProjectDirectory`）对每个状态给机器可读的
  `status` + 具体 `problem`（code / path / expected / actual），不用一句“不是项目”糊弄：
  `valid / migratable / invalid / malformed_json / unreadable / no_project_json`。
- §3.5：父目录下每个子目录各是一个项目时，父目录仍分类为 `no_project_json`，且
  `inspection.project === null`——绝不借子项目的身份自动打开错误的课
  （`tests/smart_project_inspect_test.ts` 新用例）。

## 4. Project Registry（§4 / §5）

- **存在哪里**：桌面壳 `<app local data>/.workspace/projects.json`；浏览器壳
  `<项目根>/.workspace/projects.json`——同一记录形状、同一套规则（`src-tauri/src/registry.rs`
  与 `src/service/project_registry.ts` 互为镜像）。
- **记录哪些字段（§4.1，仅此五项）**：`project_id`、`project_path`、`project_title`、
  `last_opened_at`、可选 `last_content_item_id`（读者上次所在课）。
- **为什么不是第二份 Canonical**：它是**可重建的应用级索引**，不是课程事实：
  按 id 去重、最多 200 行、原子写入、`0600`、损坏时另存 `.bak` 并按空表处理；
  写入前逐层拒绝凭据形状的键（与 Canonical 的敏感字段门同一形状）；未知字段读取时丢弃
  而不是回显。课程正文、API Key、AI Token、`project.json` 的任何拷贝都不在记录形状里。
- **更新规则（§4.2—§4.4）**：按 `project_id` 上插（refreshed / added）；同一 id 换到新路径且旧
  路径已失效 → 行跟随项目（relocated）；同一 id 出现在两个都活着的文件夹 → 不写、不合并，
  交由用户决定（duplicate，可“保留两条记录（标注副本）”或“更新项目位置”）；
  「重新定位」必须新路径里的 `project.id` 与行一致才允许，不一致就如实报错。
- **启动页（§5）**：列出全部历史项目（最近打开优先、id 稳定排序），每行区分可打开 /
  「找不到」（提供 重新定位 / 从列表移除，移除只删行、不碰磁盘），当前打开的项目有标记，
  同一 id 的副本有标记；空表/损坏表时启动页仍可用。渲染转义标题，恶意文件名不注入。

## 5. Import Formats（§14、§20—§27）

解析层契约：`parse_document(name, bytes) -> ParsedDocument { blocks, images, warnings, degraded,
usable_text }`，区块 IR 与既有 `parseMarkdown()` / `adopt_markdown_blocks` 完全相同；
每个文件一次事务，失败只降级该文件。`.md` / `.markdown` 走既有 marked 管线（透传），
不在 Rust 里再造一套 Markdown 实现。

| 格式 | parser | 保留 | 降级 / 提示 | 未支持（明确不做） |
|---|---|---|---|---|
| `.txt` `.text` | `plaintext.rs`（encoding_rs） | BOM/UTF-8/GB18030/Big5/Windows-1252 等编码识别；空行切段、段落顺序 | 全部按段落，**不猜标题**；无法解码则报错，不用替换字符凑正文 | 不做版式推断 |
| `.md` `.markdown` | 既有 marked 管线（透传） | 既有全部 Markdown 语义与图片引用 | 与原行为一致 | — |
| `.tex` `.latex` | `latex.rs`（词法级，绝不执行 TeX） | `\part`…`\subparagraph` → 标题层级；itemize/enumerate/description → 列表；quote 环境；verbatim → 代码；表格；行内语义 | 数学公式 → 代码块（源码不丢，`degraded` + 提示）；未知命令 / 环境按原文保留并聚合提示 | 不执行宏包、不访问磁盘、不调用外部程序 |
| `.docx` | `docx.rs`（zip + quick-xml 事件流） | 段落顺序、Heading1–6（含中文样式名）、粗 / 斜 / 删除线、列表（numbering.xml 语义）、表格、超链接、引用样式、行内图片（按序落位为受管素材） | 单个不支持对象产生提示，不整体失败 | Word 主题、字体、字号、颜色、页边距、页眉页脚、文本框、WordArt |
| `.epub` | `epub.rs`（zip → OPF → spine → XHTML） | 严格 spine 阅读顺序、章节标题、段落、粗斜体、引用、列表、链接、表格、图片 | 坏章节跳过 + 提示；无 h1–h6 时用 class/epub:type 名做弱标题提示 | CSS 完全不解析（字体颜色版式不进课程）；不联网 |
| `.pdf` | `pdf.rs`（lopdf 对象层 + 手写内容流词法器） | 页序 + 内容流顺序、文本层提取、字号启发式标题（大字号 + 短行）、Form XObject 递归、ToUnicode/CID 解码、损坏 `/Length` 的流恢复 | 解码失败占位符计为“未导入”提示、绝不写进正文；多栏不坐标重排 | **不做 OCR**（无文本层 → 仅 Reference + 固定提示）；不导入内嵌图片（位置不可靠）、表单、批注、脚本 |

安全上限（不可信输入）：单文件 96 MiB、单条目解压 64 MiB（ZIP 炸弹防护）、单图 24 MiB /
400 张、区块 20 000 / 单块 1.5 MB、提示最多 200 条；解析路径无 `unwrap()/expect()`，
超限一律 `Err` 或带提示跳过——不 panic、不静默丢内容。

## 6. Mapping UX（§15—§19、§28—§31）

- **映射预览仍是根级**：只展示所选目录第一层，不铺满后代文件。
- **媒体自动导入（§17）**：确认映射后，选中的 mapped folder 递归发现图片 / 视频 →
  作为 Asset 进素材库，无需逐勾选；媒体**不会**自动生成 AssetUsage、不自动插进正文（§17.1）。
- **文本 / 文档二次选择（§18）**：发现九类文档候选时弹出「选择要导入为正文的文档」——
  按原始目录分组、每行给出名称 / 相对路径 / 类型 / 大小；全选、取消全选、行点击（不只
  复选框）都能切换；媒体-only 的目录保持“一次确认”旧路径（弹窗不出现）；取消弹窗 =
  什么都不写入、计划保持未确认、源文件原处不动。
- **导入目标严格服从已确认的 Mapping Plan（§19）**：弹窗里不再创建第二套 Stage / Lesson
  推断；文档进入映射对象对应的内容链，映射到 Stage 时按既有规则创建 / 对应 Lesson。
- **一次导入 = 一个结构化事务（§28）**：单文件失败只降级该文件（PDF 无文本层、勾选外的
  文档等都是**有意的跳过**）；结果给出机器可读回执
  `document_import = { succeeded, degraded, skipped, failed, files:[{relative_path, outcome,
  reason}] }`，界面按此渲染 N 成功 / N 降级 / N 跳过 / N 失败。
- **来源保持原地（§29）**：不移动、不改名、不删除、不覆盖；权威来源清单在
  `project.settings.markdown_import_sources`（相对路径 + SHA-256），导入区块首块的
  `markdown_import` 只是兼容副本。
- **重复来源（§30）**：同 SHA 默认跳过并提示「已导入」，已编辑正文不被静默替换；来源路径
  已有较旧导入时默认跳过，用户明确选择「作为新版本导入」才追加；不做 `git add -A` 式
  自动覆盖。
- **不做系统文件过滤（§31）**：不实现 `.gitignore` / `.workbenchignore` 解析器，也不做
  目录黑名单；导入范围由「用户勾选的 mapped files / folders」+「明确支持的扩展名」
  两层自然收敛，其它类型既不自动当正文也不自动当素材。
