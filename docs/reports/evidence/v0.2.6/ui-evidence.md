## Rich-editor Markdown input contract review

- The v0.2.4 feature record explicitly promises that typing `**粗体**`, `# 标题`, `> 引用`, `- 列表`, and `` `代码` `` becomes rich formatting and removes the syntax markers.
- `app/main.js` routes each non-composition `input` event through `compileInlineAtCaret`, serializes the resulting editable DOM back to canonical Markdown, and schedules a structural conversion probe. The idle probe converts only while the editor still has focus; blur also flushes with structural conversion enabled.
- `app/markdown.js::compileInlineAtCaret` requires a collapsed selection in a text node inside the editor, with the caret immediately after a complete closer. It converts complete inline markers (`**...**`, `*...*`, `~~...~~`, and backticks). `structuralConversion` handles block syntax after the stable boundary.
- The CUA fixture observation did not involve typing: the owner rewrote a canonical paragraph fixture with literal markers, restarted the app, and read Preview. The editor serializer escapes those literal characters in plain text, so they remain literal in Preview. That action does not reproduce the documented keyboard shortcut.
- `tests/editor_compile_test.ts` exercises inline conversion by constructing a text node/caret and directly calling the compiler. The heading/Undo test assigns `block.content` and directly invokes `recordBlockTextEdit` with a prepared `retype` value. These tests cover compiler/store behavior, not browser input, idle timing, or blur wiring.
- Run4 CUA entered `Typed inline **bold** and *italic* markers.` and `# Typed heading` one character at a time; Preview rendered emphasis and an H1. Typing `- Typed list first`, Return, then `- Typed list second` left literal paragraphs in that run. The latest-client run6 list conversion and escaped-literal behavior are recorded above.
- Root later warned that the dev server may have cached its service module during CAS changes while the browser loaded the current frontend. Run6 used a fresh service/client pair after backend protocol stabilization, so it supersedes the earlier pending list and save observations; the post-reload save-label discrepancy is reported separately above.
