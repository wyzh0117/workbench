# v0.2.6 UI design system

This note records the shared visual rules currently expressed in `app/styles.css`, as observed on the candidate source tree. It is an implementation reference, not a claim that every screen has passed visual QA. The page-by-page review and unresolved checks are in the [UI audit](./v0.2.6-ui-audit.md) and [completion report](./v0.2.6-ui-redesign-completion-report.html).

## Foundation tokens

| Area | Shared values |
|---|---|
| Surface and text | `--bg #f2f4f1`, `--panel #fff`, `--panel-muted #f7f9f6`, `--text #1d2b27`, `--muted #61716b` |
| Semantic color | `--primary #14725f`, `--primary-dark #0d5b4c`, `--primary-soft #e6f2ee`, plus `--green`, `--orange`, `--danger`, and `--blue` |
| Typography | `--font-family-ui` uses Inter/system UI; `--font-family-reading` uses Charter/Songti/Noto Serif/Georgia; `--type-label`, `--type-small`, `--type-body`, `--type-section-title`, fluid `--type-page-title`, and `--line-height-copy: 1.65` |
| Spacing | `--space-1`…`--space-6`: `4 / 8 / 12 / 16 / 24 / 32px` |
| Radius | `--radius-sm/md/lg`: `7 / 12 / 18px`; controls use `--control-radius` |
| Depth | `--shadow` and `--shadow-soft` separate dialog/card depth from light surfaces |
| Motion | `--motion-fast: 120ms`, `--motion-standard: 180ms`, `--motion-emphasized: 220ms`, and `--ease-standard` |
| Controls and icons | `--control-height: 35px`, large/compact heights, `--icon-control-size`, and `--icon-size-small/medium/large`; focus uses a solid 3px primary ring with 2px offset |
| Layering | `--z-panel`, `--z-menu`, `--z-overlay`, `--z-toast`, `--z-drag`, and `--z-portal` |

The first-party stylesheet uses CSS variables for these tokens. `color-mix()` is absent from the candidate stylesheet; focus uses a solid-color outline, which has a direct older WebView fallback. The control-height token was adjusted from `2.4rem` to `35px` in response to a failing alignment contract; the status bar height is explicitly `30px`. QA's final gates passed: Deno check/test 602/602 and Rust 222/222. The final Universal candidate package hash `c4594037e0c9d4e908c9896e2aff9b39c55b23c883e19c0429fb73654d2e354f` was verified; native UI smoke remains blocked by the locked Mac.

## Page and overlay patterns

- Page headers pair an eyebrow, title, short purpose statement, and one primary action. `summary-grid`/`summary-card` surface course totals; `page-section`, `surface-card`, `list-row`, and `empty-state` provide consistent grouping without flattening each route into a generic template.
- The Launcher uses `launcher-choice-grid` to separate new, open, and import choices; it collapses at the existing 900px and 620px breakpoints. Mapping, Inbox, Board, Backlog, Publish, Versions, Media, Files, Settings, Workbench, Flow, Preview, and Free Layout each retain scoped information architecture.
- Modal content uses the shared `.overlay` / `.modal` surface, semantic `role="dialog"` / `aria-modal`, labelled headings, and the shared keyboard trap where the renderer exposes a dialog. Destructive actions use one UI-only confirmation state; cancel/Escape do not change canonical data, while confirm dispatches to the existing undoable operation.
- Breakpoints include 1150px, 900px, and 620px, plus a wide-layout rule above 1481px. Their source coverage does not replace runtime inspection at 1024, 1280, 1440, and 1728px or browser text zoom.

## Shared interaction language

- Primary actions use the green semantic accent; secondary actions are white, bordered controls. Icon-only actions have accessible names and remain keyboard-focusable.
- Shared control styling covers buttons, fields, tabs, row actions, dialogs, and transient messages. Short state changes use a toast; local recoverable problems stay inline; a dialog is reserved for an explicit decision or blocking failure.
- Focus visibility is not suppressed. Motion honors the existing reduced-motion media query. Overlay and modal keyboard behavior remains subject to the page-by-page accessibility audit.
- Layout panels share stable frame sizing; the product shell retains independently collapsible navigation and inspector rails.

## Scope and known ceiling

The token layer is evidence of consistency at the CSS foundation; it does not establish that every page has been visually inspected at 1024, 1280, 1440, and 1728 pixels, that every hover/error/loading state is balanced, or that every dialog has passed a focus-trap audit. A run7 browser sweep observed only the Project Overview and shared shell at those four widths. The shell had no horizontal overflow and the title cluster kept gaps at all four sizes. The client stopped responding to click and keyboard activation before the remaining routes or sidebar states could be reviewed; system text scaling was not changed. See the [UI evidence notes](./evidence/v0.2.6/ui-evidence.md) and [UI audit](./v0.2.6-ui-audit.md).
