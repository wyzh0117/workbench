# v0.2.5 — 媒体库闪烁根因（需求见 `V0.2.4_Closure_and_V2_Roadmap_Revision.md` §6.1 / §7）

只讲 §6.1 那条真实路径：导入大量素材 → 媒体库 → 滚到底 → 往回滚。
行号均指当前工作树；"修改前"指 `git show HEAD:app/canvas.js`（对比见 `git diff -- app/canvas.js`）。

## Media Flicker Root Cause — 大白话说明

### 1. 为什么会开始反复加载？

缓存像一个只有 32 格的相册架（修改前 `canvas.js:118`），规则是"从最前面扔掉"。旧版每次**读取**都会把这张照片塞回架子末尾（修改前 `canvas.js:151-152`）；这里的"读取"只是重画时 `views.js:110-111` 调的那一次 `get()`，不代表用户真的看了它。媒体库一次把全部素材画进 DOM、没有分页（`views.js:2222`），所以重画一遍就把架子顺序彻底改成"从上到下"。

新缩略图放进来 → 格子超过 32 → 从最前面扔一张。被扔的那张很可能还在屏幕上，而扔掉它的同时把它的取件码（`blob:` 网址）也作废了（修改前 `canvas.js:438-445`）。屏幕上那张 `<img>` 的网址当场失效，卡片退回"等待加载"，于是再读一次，再挤掉一张。

真正让它停不下来的是"送一封信就把整栋楼拆了重盖"：旧版每读完一张图都在微任务里触发整页重建（修改前 `canvas.js:427` 的 `scheduleNotify()` → `main.js:10504` → `render()`），而 `render()` 是 `root.innerHTML = …`（现 `main.js:8652`），120 张卡片全部换新、身份全部丢失；重建后 `observe()` 把卡片重新登记给 IntersectionObserver（观察者：浏览器用来报告"这个元素进入视野了吗"的机制），而浏览器对刚登记的元素必定补发一条"进入视野"记录 → 又开一次读取。循环闭上了。

### 2. 为什么往回滚更容易触发？

"扔哪一张"跟着重画时 DOM 从上到下的顺序走，架子最前面永远是列表靠上的卡片。往下滚时，被扔的正好是快要滚出视野的卡片，用户看不出来；往回滚时，列表靠上的卡片是即将进视野的那一批——刚加载完就被扔、扔掉就重来，抽搐正好发生在眼睛盯着的方向，`rootMargin: 160px`（`canvas.js:283`）还让它们一登记就命中。
注意：这条方向性是从"`get()` 重排 + 渲染顺序 + 容量 32"推出来的，修改前没有跑过向下/向上的 A/B 对比；测试 `reading a preview does not reorder the eviction queue` 钉住的是修法，不是这个推断。

### 3. 为什么最后连其他地方也无法点击？

有代码依据的两条：
- 预览完成在微任务里同步重建整页（解析 120 张卡片 + 重绑事件 + 复原滚动和焦点），循环不停则重建不停，输入排在后面。
- `render()` 会主动打断正在进行的指针动作：`main.js:8650 cancelActivePointerDrag?.()`。按下与抬起之间节点被换掉，绑在旧节点上的监听（`bindActionControls`）随节点一起消失。

只能算推断的一条：这种情况下浏览器把 `click` 派发给"最近的共同祖先"，`closest("[data-action]")` 就找不到按钮了。测试文件第 18-20 行写了这句话，但**没有任何断言钉住它**，所以本条记为未证明。

排除掉的一条猜测：不是"N 个并发读取压满主线程"。并发上限修改前后都是 2（`canvas.js:136`）；旧版慢在重复读取和反复整页重建，不是同时读太多。

### 4. 真正是哪一个状态 / observer / async request 在循环？

- 状态：`ready → loading`。`get()` 只要 `entries` 里没有这个 key 就返回 `{loading:true}`（修改前 `canvas.js:156`；现 `canvas.js:188-192` 区分出 `released`）。
- 观察者：IntersectionObserver 的**重新登记**，不是 enter/leave 抖动——旧回调对 `isIntersecting === false` 直接 `continue`（修改前 `canvas.js:203`），离开视野根本不处理，也没有任何"滚出视口就删除"的代码。
- 异步请求：`load()` 的 `finally` 里那句 `scheduleNotify()`（修改前 `canvas.js:427`）是再触发点。
- 淘汰器：`cache()` 按插入顺序扔最前面并 revoke 其 URL（修改前 `canvas.js:438-445`）。

一句话：`load 完成 → notify → render → observe → load`。

### 5. 最终怎样修的？

把"寄到一张照片就重盖整栋楼"改成"只换那一格"：落定的预览走 `onPatch` 就地改写那一个 frame（`canvas.js:745-757` → `main.js:8585-8618`），整页重建退化为"没有任何 frame 能改"时的兜底；正在显示的卡片把自己的缓存钉住（`canvas.js:645-674`，容量 = 在页卡片数 + 32 历史，硬上限 240）；真要腾内存时先重画、再作废 URL，并把该卡片标成 `released`，显示"缩略图已释放"+ 重试按钮（`canvas.js:722-738`、`views.js:223`）；`get()` 改成只读（`canvas.js:184-188`）；已落定/在途的卡片不再重新登记（`canvas.js:290-298`）；`observe()` 移到滚动复原之后（`main.js:8659-8663`）；等待队列有界并把"卡片没了"的排队读取就地作废（`canvas.js:353-367`、`394-406`）。

### 6. 为什么这次修法不会继续留下同类型隐患？

循环要成立必须同时满足四件事，现在每件事各有一道闸门和一条测试：完成不重建、显示中不被淘汰、同一素材不重复登记、状态机只往前走。抽掉任意一条循环就断，而四条同时被 `media_preview_stability_test.ts` 的第一个用例钉着。更关键的是几何与身份是**结构性**保证：全文件只有一处写 `data-asset-preview-key`（`views.js:199-211`），所有状态都画在同一个盒子（`styles.css:391-413`）里，新加一个状态想绕过这个盒子，测试直接红——不是四处分歧式打补丁。

## 未被自动化闭合的部分

`tests/media_preview_stability_test.ts` 用手写 DOM + 行为化 IntersectionObserver 驱动真实的 `AssetPreviewCache` 与 `views.js`，跑通 12 个用例；以下必须由真实 Tauri 窗口才能证明：

1. **真实指针滚动**：120+ 张卡上的滚轮/触控板来回滚、惯性滚动与快速反向。测试里 `scrollTo()` 是直接改可见集合，不产生真实几何、也不测 `rootMargin: 160px` 的实际边界。
2. **真实 IO 时序**：浏览器对"刚登记元素"补发初始记录的确切时机，以及 `observe()` 放在滚动复原之后（`main.js:8659-8663`）带来的差别——这条改动没有任何断言。
3. **点击真的落得上**：测试头注释里"按下与抬起之间元素被替换 → `click` 落在共同祖先"只有注释，没有断言。`grid_pointer_test.ts` 覆盖的是画布 Grid 表面，且是既有测试，不针对媒体库。
4. **真实素材体积**：fixture 是 6 字节 PNG。真实几 MB 图片下的 96 MiB 字节预算、WebView 里的图片解码开销、以及"在页卡片被标成已释放"在生产规模下多常发生，都没有量化证据。
5. **重试按钮的合成点击已闭合，真实指针未闭合**：`the 重试预览 button the real patch paints is bound by the real binder and takes the click` 用例覆盖了 patch 路径的 `bindActionControls(frame)`（`bound("click") === 1`，点击后恰好发起一次新读取、只重画那一格）；但它走的是合成 `click()`，真实指针按压落在按钮上仍需真实窗口验证（与第 1 条同一原因）。
6. **token 失效路径**：`evict()`/`retry()` 里的 `bumpToken`（`canvas.js:728`、`206`）没有用例驱动"在途读取 + 淘汰/重试并发"；现有迟到响应用例只走 `clear()`/generation。
7. **容量语义的已知妥协**：`isLive()` 判的是 `isConnected`（在 DOM 里），不是"在视野里"。媒体库不分页，所以超过 `maxTotalEntries = 240`（或超过字节预算）时，`pickVictim()` 会退化成淘汰**在 DOM 里**的卡片（`canvas.js:716`），表现为滚动到很大库的某些卡片显示"缩略图已释放"要手点。这是 §11 允许的有界淘汰，但对 240+ 素材的真实库没有跑过。
8. **视频/音频/PDF 预览面**：本文件的循环用例只用 image 素材；`previewAssetVideoSource` 与 PDF 分支只由 `video_frame_test.ts` 等覆盖，与滚动稳定性没有串联。
